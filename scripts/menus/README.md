# Menu data pipeline

Full restaurant menus are generated from each chain's own published nutrition
data rather than typed by hand. Generated files live in `src/data/` (a small
restaurant record) and `src/data/menus/` (the item list, loaded on demand).

```bash
npm run menus:validate     # check every item and size
npm run menus:timhortons   # re-crawl Tim Hortons and regenerate
npm run menus:burgerking   # re-crawl Burger King and regenerate
npm run menus:aw           # re-crawl A&W and regenerate
npm run menus:wendys       # re-crawl Wendy's and regenerate
npm run menus:firehouse    # re-crawl Firehouse Subs and regenerate
npm run menus:kfc          # re-download KFC's nutrition PDFs and regenerate (needs pdftotext)
npm run menus:pizzahut     # re-download Pizza Hut's PDF and regenerate (needs pdftotext)
npm run menus:marybrowns   # re-download Mary Brown's PDF and regenerate (needs pdftotext)
npm run menus:thaiexpress  # re-download Thai Express's chart and regenerate (needs pdftotext)
npm run menus:manchuwok    # re-download Manchu Wok's PDF and regenerate (needs pdftotext)
npm run menus:harveys      # regenerate Harvey's from raw/harveys.tsv
npm run menus:dq           # regenerate Dairy Queen from raw/dq.tsv
npm run menus:littlecaesars # regenerate Little Caesars from raw/littlecaesars.tsv
npm run menus:mcdonalds    # regenerate McDonald's from raw/mcd.json
```

PDF-based sources need `pdftotext` (xpdf or poppler). Their extracted tables
are kept in `raw/` so the menus can be regenerated without it.

`menus:validate` confirms, for every item and every size, that the default
ingredients sum exactly to the published total, that no value is negative, and
that every item offers add-ons.

TypeScript scripts are run through `run.cjs`, which bundles them with esbuild
(`node scripts/menus/run.cjs <script.ts> [args]`). Shared output code lives in
`lib.ts`.

## Sources

| Restaurant | Source | Notes |
|---|---|---|
| Tim Hortons | Public menu API (Sanity GraphQL, dataset `prod_th_ca`) | Fetched by `fetch-rbi.cjs`, generated by `gen-rbi.ts`. Totals use the "as served" values; default add-ins become removable ingredients and optional add-ins become add-ons, each with official nutrition. |
| Burger King | Public menu API (Sanity GraphQL, project `kjfd81ul`, dataset `prod_bk_ca`) | Same pipeline as Tim Hortons. |
| A&W | Public menu API on web.aw.ca (`/api/menu/` and `/api/menu/<slug>`) | Fetched by `fetch-aw.cjs`. Each item's ingredient list is A&W's own; where two versions differ by one ingredient (lettuce-wrapped, with cheese…) that ingredient carries the official calorie difference. |
| Wendy's | Menu and nutrition services behind order.wendys.com (`web-client-gateway/menu/getSiteMenu` for an Ottawa restaurant, `NutritionServices/rest/nutritionalData`) | Fetched by `fetch-wendys.cjs`. Each ingredient's nutrition is queried on its own, so default ingredients and add-ons carry Wendy's official values. |
| KFC | Nutrition guides linked from the kfc.ca footer (main menu + Kwench drinks PDFs) | `fetch-kfc.cjs` extracts the English tables into `raw/kfc.tsv` (kept in the repo, since it needs `pdftotext`). Add-ons (cheese, Deluxe it up, gravy, dips, cold foam) use KFC's own values; the online-ordering catalog is not used because many of its nutrition values are placeholders. |
| Firehouse Subs | Public menu API (Sanity GraphQL, dataset `prod_fhs_ca`) | Same pipeline as Tim Hortons. |
| Dairy Queen | Nutrition page (dairyqueen.com/en-ca/nutrition/food-treats) | The site blocks scripted requests, so `raw/dq.tsv` was captured in a browser (checksum-verified). DQ's add-ons (Blizzard mix-ins and toppings by size, burger toppings, sauces) are add-ons with DQ's values. Three rows with broken source data are skipped. |
| Little Caesars | 2026 nutritional guide image on littlecaesars.ca/en-ca/menu/nutrition | The downloadable PDF there is the 2016 edition, so the current guide was transcribed into `raw/littlecaesars.tsv` and every row sanity-checked (calories vs. macros). Whole pizzas are official; a slice is one eighth. Toppings, stuffed crust and Crazy Crust are add-ons per size. |
| Pizza Hut | Nutrition PDF linked from pizzahut.ca/nutrition | Per-slice values for every pizza, crust and size; toppings per slice by size; wings and wing sauces per piece. |
| Mary Brown's | Nutrition PDF linked from marybrowns.com/menu | Published per serving; totals are whole items. A fat typo (Large Taters) is corrected, and the Fan Favourite 6 PC (≈2.5× its own pieces) uses the sum of the official pieces. |
| Thai Express | Nutrition chart linked from thaiexpress.ca/nutritional-facts | Meals are the sum of official parts (sauce & vegetables or broth + protein + rice / noodles + egg). Vegan / gluten-friendly rows are told apart by order (icons in the PDF). |
| Manchu Wok | Nutrition PDF linked from manchuwok.com | Read with `pdftotext -raw` because the PDF has overlapping text layers. Portions 5 / 6 / 7 / 16 oz become sizes. One broken row (Spring Roll) is skipped. |
| Harvey's | Nutrition & allergen page (harveys.ca/en/nutrition.html) | The site blocks scripted requests, so `raw/harveys.tsv` was captured in a browser (see below). Buns, patties, cheese, bacon and every garnish are listed separately, so burgers, sandwiches and breakfast items are built entirely from official parts. |
| McDonald's | Product pages and the `/dnaapp/itemDetails` nutrition API on mcdonalds.com | The site blocks scripted requests, so `raw/mcd.json` was captured in a browser (see below). Includes McDonald's published per-ingredient calories. |

### Refreshing Harvey's data

1. Open `https://www.harveys.ca/en/nutrition.html` in a browser.
2. In the developer console, read every `.nutrition-product-content` panel inside
   each section and print one tab-separated line per item:
   `section, code, name, serving g, calories, fat, sodium, carbs, protein`.
3. Save the lines as `raw/harveys.tsv` and run `npm run menus:harveys`.

### Refreshing Dairy Queen data

1. Open `https://www.dairyqueen.com/en-ca/nutrition/food-treats/` in a browser.
2. In the developer console, read every table row and print one tab-separated
   line per item: `section heading, name, calories, fat, sodium, carbs, protein`.
3. Save the lines as `raw/dq.tsv` and run `npm run menus:dq`.

### Refreshing McDonald's data

1. Open `https://www.mcdonalds.com/dnaapp/itemDetails?country=CA&language=en&showLiveData=true&item=200944` in a browser.
2. In the developer console, collect the product links from `/ca/en-ca/full-menu.html`,
   read each product page's `data-product-id`, and fetch
   `/dnaapp/itemDetails?country=CA&language=en&showLiveData=true&item=<id>`.
3. Save the result as `raw/mcd.json` in the compact format the generator reads:
   `[category, name, calories, fat, carbs, protein, sodium, fibre, sugar, servingSize, [[ingredient, isDefault, calories], ...]]`.
4. Run `npm run menus:mcdonalds`.
