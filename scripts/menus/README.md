# Menu data pipeline

Full restaurant menus are generated from each chain's own published nutrition
data rather than typed by hand. Generated files live in `src/data/` (a small
restaurant record) and `src/data/menus/` (the item list, loaded on demand).

```bash
npm run menus:validate     # check every item and size
npm run menus:timhortons   # re-crawl Tim Hortons and regenerate
npm run menus:burgerking   # re-crawl Burger King and regenerate
npm run menus:aw           # re-crawl A&W and regenerate
npm run menus:wendys       # re-crawl Wendy's and regenerate
npm run menus:firehouse    # re-crawl Firehouse Subs and regenerate
npm run menus:kfc          # re-download KFC's nutrition PDFs and regenerate (needs pdftotext)
npm run menus:pizzahut     # re-download Pizza Hut's PDF and regenerate (needs pdftotext)
npm run menus:marybrowns   # re-download Mary Brown's PDF and regenerate (needs pdftotext)
npm run menus:thaiexpress  # re-download Thai Express's chart and regenerate (needs pdftotext)
npm run menus:manchuwok    # re-download Manchu Wok's PDF and regenerate (needs pdftotext)
npm run menus:osmows       # re-fetch Osmow's calculator data and regenerate
npm run menus:subway       # re-download Subway's PDF and regenerate (needs pdftotext)
npm run menus:pitapit      # re-download Pita Pit's guide and regenerate (needs pdftotext)
npm run menus:muchoburrito # re-fetch MUCHO Burrito's calculator data and regenerate
npm run menus:works        # re-download The WORKS' guide and regenerate (needs pdftotext)
npm run menus:bostonpizza  # re-fetch Boston Pizza's nutrition page and regenerate
npm run menus:barburrito   # re-fetch Bar Burrito's calculator and regenerate
npm run menus:freshii      # re-download Freshii's guide and regenerate (needs pdftotext)
npm run menus:tacobell     # re-fetch Taco Bell's nutrition menu data and regenerate
npm run menus:starbucks    # re-crawl Starbucks (slow, one request at a time) and regenerate
npm run menus:noodlebox    # re-download Noodlebox's nutrition spreadsheet and regenerate
npm run menus:redswan      # re-download Red Swan's nutrition guide and regenerate (needs pdftotext)
npm run menus:kettlemans   # re-crawl Kettleman's menu pages and regenerate
npm run menus:madradish    # regenerate Mad Radish from raw/madradish.tsv
npm run menus:local        # regenerate the estimated local spots from local/*.txt
npm run menus:tahinis      # regenerate Tahini's from raw/tahinis.tsv
npm run menus:swisschalet  # regenerate Swiss Chalet from raw/swisschalet.tsv
npm run menus:harveys      # regenerate Harvey's from raw/harveys.tsv
npm run menus:dq           # regenerate Dairy Queen from raw/dq.tsv
npm run menus:littlecaesars # regenerate Little Caesars from raw/littlecaesars.tsv
npm run menus:mcdonalds    # regenerate McDonald's from raw/mcd.json
```

PDF-based sources need `pdftotext` (xpdf or poppler). Their extracted tables
are kept in `raw/` so the menus can be regenerated without it.

`menus:validate` confirms, for every item and every size, that the default
ingredients sum exactly to the published total, that no value is negative, and
that every item offers add-ons.

TypeScript scripts are run through `run.cjs`, which bundles them with esbuild
(`node scripts/menus/run.cjs <script.ts> [args]`). Shared output code lives in
`lib.ts`.

### Refreshing Harvey's data

1. Open `https://www.harveys.ca/en/nutrition.html` in a browser.
2. In the developer console, read every `.nutrition-product-content` panel inside
   each section and print one tab-separated line per item:
   `section, code, name, serving g, calories, fat, sodium, carbs, protein`.
3. Save the lines as `raw/harveys.tsv` and run `npm run menus:harveys`.

### Refreshing Dairy Queen data

1. Open `https://www.dairyqueen.com/en-ca/nutrition/food-treats/` in a browser.
2. In the developer console, read every table row and print one tab-separated
   line per item: `section heading, name, calories, fat, sodium, carbs, protein`.
3. Save the lines as `raw/dq.tsv` and run `npm run menus:dq`.

### Refreshing Swiss Chalet data

## Local spots (estimated)

Independent and regional spots that publish no nutrition data are generated by
`gen-local.ts` from one menu file per spot in `local/` (the home-page order is
in `local/ORDER`). Each file lists the spot's real menu, taken from its own
website or ordering page where one exists (the `source:` line says where; a
few spots have no public menu, and their files say so), and maps every item to
a reference recipe in `estimate.ts`:

```
Pork Original Ramen = ramen.tonkotsu @ 583-983 :: pork broth, noodles, pork, nori, seasoned egg
Chicken Shawarma Sandwich = wrap.chicken ; Small=0.8, Large=1.2
```

- `xK` scales the reference portion; `; Label=factor` adds sizes or options.
- `@` uses calories the spot posts on its menu (Ontario requires them): a
  number, a range (spread across the sizes, or offered as low / high ends), or
  a per-piece figure such as `@ 70/wing` multiplied by each size's count. The
  macros keep the reference recipe's balance.
- `::` lists the dish's ingredients as the menu describes them; they become the
  removable parts, sized from `ingredients.ts` and summing exactly to the total.

Every local item is labelled as estimated in the app, and items that use posted
calories say so.

`npm run menus:accuracy` measures the reference recipes against the ~400 dishes
whose calories a spot posts: for each, what the recipe alone would have
estimated versus the posted figure. For main dishes the median gap is about
25%, with roughly two in three within 35%. A recipe that runs high or low the
same way at several restaurants is a sign it needs recalibrating (sit-down
tenders, kids' meals, Caesar salads and fish & chips were raised this way).

### Starbucks

`fetch-starbucks.cjs` reads the ordering menu behind starbucks.ca/menu
(`/apiproxy/v1/ordering/menu`, then each product's per-size nutrition) into
`raw/starbucks.json`. The site rate-limits aggressively, so the script makes one
request at a time (a full crawl takes several minutes); if it is refused
(HTTP 403), wait and run it again later.

### Refreshing McDonald's data

1. Open `https://www.mcdonalds.com/dnaapp/itemDetails?country=CA&language=en&showLiveData=true&item=200944` in a browser.
2. In the developer console, collect the product links from `/ca/en-ca/full-menu.html`,
   read each product page's `data-product-id`, and fetch
   `/dnaapp/itemDetails?country=CA&language=en&showLiveData=true&item=<id>`.
3. Save the result as `raw/mcd.json` in the compact format the generator reads:
   `[category, name, calories, fat, carbs, protein, sodium, fibre, sugar, servingSize, [[ingredient, isDefault, calories], ...]]`.
4. Run `npm run menus:mcdonalds`.

## Product photos

`fetch-images.cjs <brand>` collects photo URLs from a chain's own menu data into
`images/<file>.json` (product name → URL). `writeMenu` (via
`attach-images.mjs`) attaches a photo to each item whose name matches, and the
app loads it straight from the restaurant's own CDN, lazily, hiding it if it
fails to load.

- **Fetched by script** (`fetch-images.cjs`): Tim Hortons, Burger King and
  Firehouse Subs (Sanity), Starbucks, Taco Bell, Wendy's, KFC, Freshii, A&W and
  Kettleman's. Photos that don't load are dropped, `ALIASES` maps our item
  names to the chain's own product names where they differ, and `EXTRA` adds
  photos from the chain's ordering site for items its menu pages don't show.
- **Captured in a browser** (menus that only render with JavaScript, block
  scripted requests, or appear only on the chain's ordering site after picking
  a store): McDonald's, Subway, Harvey's, Swiss Chalet, Boston Pizza, Pizza Hut,
  Dairy Queen, The WORKS, Pita Pit, Osmow's, Tahini's, MUCHO Burrito, Bar
  Burrito, Mary Brown's, Thai Express, Manchu Wok, Noodlebox and Mad Radish.
  These files are keyed by our own item names; refresh them by hand.
- **Local spots** (`images/local/<id>.json`, attached by `gen-local.ts`):
  photos from the spot's own website or ordering page where it shows them —
  Kinton, 3 Brothers, Sushi Sama, Shawarma Prince, CoCo, Suzy Q, St. Louis,
  Lone Star and Pita Bell Kabab.
- Where a chain shows one official photo per format rather than per recipe,
  every item of that format uses it: Pita Pit's signature items (its pita /
  rice bowl / salad photos), Thai Express stir-fries and Shak-a-Bowls, Freshii
  smoothie bowls and Lone Star fajitas.
- **Delivery-app fallback** (`images/delivery/[local/]<file>.json`): the photos
  each restaurant uploaded to its own Uber Eats listings (Ottawa locations,
  several stores merged where one shows more) and, for Pizza Hut, DoorDash —
  captured from the store pages in a browser. They are used only for items the
  sources above don't cover, and a dish named as a wrap / salad / bowl only
  takes a photo whose name says so too. Listing names are cleaned of menu
  codes, calorie counts and sizes; `images/delivery/aliases.json` pairs dishes
  named differently there ("Chicken Shoyu Ramen" → "Shoyu - Chicken Broth"),
  and exclusions go in `images/exclude.json` under `delivery/<file>`.
- Not covered: pizzas at Gabriel Pizza and Topper's (their listings show one
  photo per size, not per recipe), items no listing carries (Harvey's
  breakfast, Pizza Hut pastas and wraps), estimated local dishes with no
  counterpart on the spot's real listing, and items a restaurant doesn't
  picture anywhere (mostly bottled drinks, sauces and add-ons).

Matching never crosses a product type ("Berry Smoothie" doesn't take "Berry
Smoothie Bowl"'s photo, and a wrap doesn't take the sub's), and a one-word item
name only takes a longer photo name when the extra words are sizes ("Latte" →
"Latte Small"), never another dish ("Banana" ≠ "Banana Split"). Accents are
ignored ("Jalapeño" = "Jalapeno"). `images/exclude.json` lists items whose
closest photo shows a different dish.

```bash
npm run menus:images -- timhortons   # then regenerate that chain
```

Stored photo URLs point at the largest original a host offers
(`upgrade-images.cjs`, also run by `fetch-images.cjs`: WordPress resized copies
→ the uploaded original, Wendy's medium → large shots). In the app,
`photoUrl()` (src/components/ui.tsx) asks resizing CDNs (Sanity, Contentful,
Scene7, Subway, Harvey's / Swiss Chalet, Dairy Queen, Framer) for ~300 px
thumbnails and ~1000 px for the large item photo, so both stay sharp on
high-density screens.

## Restaurant logos

`src/data/logos.ts` maps each restaurant to its official logo, loaded at
runtime: the logo or app icon from the restaurant's own website, or the
brand's logo file on Wikimedia for chains whose site only offers a tiny
favicon. Every entry was checked visually; spots that publish no logo of their
own show an initials badge instead.

## Plausibility audit

`npm run menus:audit` (`audit.ts`) flags numbers that can't be right even when
they match a source: calories far from 4·protein + 4·carbs + 9·fat, sauce or
vegetable portions with implausible calories, oversized single items, sizes
that shrink, builder-option outliers, duplicates and extreme sodium.

Every generator passes its menu through `reconcile.mjs`, which keeps the
published calories and repairs missing or misprinted macros (Wendy's Canada's
feed has no carbohydrates; Firehouse Subs gives some items calories only;
Osmow's lists one tahini at "601225" g of fat), rebalancing ingredient
breakdowns so they still add up. Known source misprints are left out entirely
(Pita Pit's Chipotle Crunch Sauce, listed at 980 kcal for every size). The
remaining audit flags were checked against the sources and are the chains'
published values (e.g. Pita Pit XL sauce portions, Boston Pizza's honey dill
dip, family packs).
